# 6. Building Block View

| Component | Path | Responsibility |
|---|---|---|
| Reusable workflow | `.github/workflows/factory.yml` | the 15-stage pipeline as 9 jobs (chapter 5) |
| Consumer workflow (per target) | `.github/workflows/code-weaver.yml` | short & stable: `uses: MelvinKl/code-weaver/.github/workflows/factory.yml@v0.1.0` (a version tag, never a moving branch), `with:` inputs, `GH_TOKEN` via `secrets:`, the `labeled`-only issue trigger + manual dispatch |
| trigger | `factory.yml` `trigger` job | fetch the issue; gate on the trigger label or manual dispatch; record issue number/title/body + the run baseline (ref + change-set diff) as state; idempotency lock on in-progress runs |
| setup-pi | `.github/actions/setup-pi/` | verify (never install) pi: presence → configuration (scans every `.pi` candidate file — the shipped `mcp.json` is a registry without a backend URL and is skipped) → backend reachability → model in the configured set → headless `pi --print` smoke check |
| baseline | `.github/actions/baseline/` | cut `ai/code-weaver/<n>` at the target's head (reuse the branch when it exists); record `baseline.sha` + `baseline.diff` as state |
| extract-stage | `.github/actions/extract-stage/` | stages 4+5: pi derives the delta Gherkin — **its context is the `@`-file slice** (oracle + arc42 markdown + `README.md` + the baseline diff, handed to pi as `@`-file arguments; pi reads the named files as context before answering); the prompt tolerates arc42 structure variance (proceeds on the readable parts) and **never edits an existing feature file**; the guard pins the delta shape — exactly one new file named after the topic the delta covers (never after the issue — the oracle is structured by topic), and a changed existing file is reverted and the stage re-runs |
| plan-stage | `.github/actions/plan-stage/` | stages 6+7: one Jira-ticket-style plan per issue at `plans/<n>.md`; the planner's context = the changed requirements + the arc42 markdown (`docs/` files — the top-level `PLAN.md` where a target has no doc dir) + the README, referenced by path (the path-referenced slice) |
| implement-stage | `.github/actions/implement-stage/` | stages 8+9: works the plan one open task at a time (the plan is a live state tracker, injected in full as the one `@`-file); keep the arc42 set complete, the README current; the guard's allow set excludes the plan dir and re-allows exactly the current issue's plan file (another issue's plan is a reverted violation); a requirement edit loops back to stage 6 |
| review-stage | `.github/actions/review-stage/` | stages 10+11: run the target's suite (`make test` → the stdlib-only runner) — the suite executes every scenario; pi judges only the Scenarios of the feature files this run changed against the output (the review call's context is path-referenced — test output + the changed feature files; a run that changed no requirements passes vacuously); the per-scenario verdict block is the oracle; the fix loop is bounded; per-iteration logs go to the state dir (artifact), never the tree |
| pr-open | `.github/actions/pr-open/` | stage 12: push the AI branch; open (or update) the PR `ai/<n>` → `target-branch`; the **PR body is generated by pi** (`pi-prompts/pr-body.md` via the `pi-run` action) **from the requirements, the plan and the review** — the template assembler is the fallback when the pi call produces nothing |
| gates-stage | `.github/actions/gates-stage/` | stages 13+14: poll every PR-triggered workflow until green; fix red gates and re-poll, bounded; **no merge call exists** |
| report | `.github/actions/report/` | stage 15: complete the PR body (the final status report) — listing the run's usage totals (total input tokens, total output tokens, total cost) assembled from the per-call usage records in the state dir (a state file that travels with the run's state artifacts like every other stage value: each stage's artifact carries the cumulative ledger, so the totals cover every pi call the run made, and a stage that never ran contributes nothing) — the cost derived from that recorded usage, keyed on the run's resolved `llm-model`, with the rate used listed (a model with no rate entry is listed as unpriced — chapter 10); comment the source issue; append the **AI-activity section to the arc42 markdown** — the first file under `doc-dir`, falling back to the top-level `PLAN.md` where a target has no doc dir (chapter 1 carries it in this repo) |
| pi-run | `.github/actions/pi-run/` | the declarative headless primitive: `pi --print --mode json --model <m>` — instructions folded into the user text, context referenced by path, the plan files injected in full; records the call's input & output token usage in the run's usage ledger (the state-dir file that travels with the artifacts) as the call finishes |
| shared plumbing | `.github/scripts/common.py`, `stages.py`, `gherkin-validate.py` | state dir, loop caps, the guard, `pi_invoke` (the two context slices; each finished call appends its input & output token counts as one usage-record line to the `tokens.txt` ledger in the state dir — a call that left no usage record appends nothing), crash diagnostics, the official-parser Gherkin validator (**skipped-not-failed** where the parser port is absent), the shared bounded loop machinery |
| prompt templates | `pi-prompts/{requirements,plan,implement,review,pr-body}.md` | the stage instructions (handed to pi as user text — pi's default system prompt stays in place; the thinking level is never pinned — pi-jev chooses it per prompt) |
| oracle | `requirements/` (14 files, 130 scenarios) | the Gherkin requirements the implementation must fulfil |
| arc42 set | `docs/01…11-*.md` | this documentation — one chapter per file; chapter 1 carries the AI-activity section the report stage appends to |
| tests | `tests/run.py` (stdlib-only runner) + `tests/test_*.py` | the validator's unit tests, the stream-capture tests, the trigger-contract tests, and the stage-contract tests; auto-discovered by the stdlib runner and by pytest alike |
