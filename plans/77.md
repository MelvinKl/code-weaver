# Issue 77 — README top warning: runs are startable by anyone who can create or tag issues, and they consume tokens and cost — use the workflow in private repos only

## Summary

The README carries no warning about the factory's trigger surface or its
cost. The run's delta adds four **new** scenarios to
`requirements/safety.feature` (no standing scenario is altered): the README
must present a prominent warning **at its top** (before the factory
description, above the usage and consumption sections), and that warning
must (a) advise using the code-weaver workflow only in a private repo,
(b) state that everyone who can create or tag issues can start a factory
run, and (c) state that such a run consumes tokens and creates cost for the
repo. Implementation = the warning itself, a stdlib-only contract test
pinning all four scenarios, and refreshing the documented oracle counts
(161 → 165 scenarios) in the README and arc42 chapters so the standing
documented-counts scenario stays green against the grown tree.

## Description

- **The delta.** `requirements/safety.feature` gains four `@safety`
  scenarios (pure additions, plus a header comment recording them):
  "The README carries a prominent warning at its top", "The README warning
  advises using the workflow only in a private repo", "The README warning
  names who can start a factory run", "The README warning states what such
  a run consumes". All four are **new** requirements — no existing scenario
  of the file (or of the oracle) is edited, so there is no in-place
  scenario to keep consistent; the work is to make the README fulfil them.
- **The gap.** `README.md` opens with the title and goes straight into the
  factory description ("An **AI software factory that creates
  programs**…"), then the stage list, `## Consume it (by ref — never
  copy-paste)` (usage), `## Inputs` (consumption) and the layout — with no
  statement that the trigger surface (a `labeled` issue event, or a manual
  dispatch — chapter 7; `labeled-only-trigger.feature`) means *everyone who
  can create or tag issues* in a target repo can start a run, and that each
  run consumes tokens whose cost lands on the repo (the usage/cost
  accounting of chapters 7/10 and `cost-and-token-usage.feature`).
- **The ripple.** The delta grows the oracle from 161 to **165** scenarios
  (`safety.feature` 15 → 19; the file count stays 15 — extended in place,
  no new file). Six stated counts in the doc surfaces still say 161
  (README: repository-layout line and Requirements section; chapter 1:
  introduction, twice; chapter 6: oracle table row; chapter 11: glossary
  entry). The standing scenario `requirement-extraction.feature::The
  documented oracle counts match the requirements tree` and its pinning
  test read those surfaces against the tree — the stated figures must move
  to 165 or that standing scenario is left unfulfilled.
- **Tension with the arc42, called out and resolved.** Chapter 4 states the
  target is "Any GitHub repo" and chapter 8 records the factory's own
  *public* repo dogfooding the published line. The new warning is
  **advisory, not a compatibility claim**: it tells maintainers of target
  repos to prefer a private repo because a public repo's issue surface
  (anyone who can create or tag issues) can start token-consuming,
  cost-bearing runs — an economic-exposure statement, orthogonal to the
  "works in any repo" compatibility statement and to the owner's own
  knowing dogfood choice. The arc42 set therefore needs **no edit**; the
  scenarios pin only the README surface, and the implement stage's
  "keep the arc42 set complete, README current" job (chapter 6) is met by
  the in-place count refreshes and the README change below.

## Acceptance Criteria

- **AC1** — `safety.feature::The README carries a prominent warning at its
  top` (new): the README's opening presents a warning at the top, before
  the factory description, above the workflow's usage and consumption
  sections.
- **AC2** — `safety.feature::The README warning advises using the workflow
  only in a private repo` (new): the top warning advises using the
  code-weaver workflow only in a private repo.
- **AC3** — `safety.feature::The README warning names who can start a
  factory run` (new): the warning states that everyone who can create or
  tag issues can create a workflow run of the factory.
- **AC4** — `safety.feature::The README warning states what such a run
  consumes` (new): the warning states that such a run consumes tokens and
  creates cost for the repo.
- **AC5** — `requirement-extraction.feature::The documented oracle counts
  match the requirements tree` (existing, unaltered by this delta — must
  stay fulfilled): the stated counts in the README and arc42 chapters equal
  what the requirements tree holds (15 files, 165 scenarios after this
  delta).
