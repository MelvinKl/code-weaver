# Issue #43 — Run cost and token usage in the report; token budget removed

**Summary**

Two coupled changes to the factory. (1) **The final status report (stage 15)
carries the run's total cost and token usage**: every pi call's input and
output token counts are recorded in the run's state as the run proceeds (the
record travels with the run's state artifacts, like every other stage value),
and the report stage assembles those records into run totals — total input
tokens, total output tokens, and total cost — in the PR body, the source-issue
comment and the arc42 AI-activity section, for successful runs and for runs
that stopped early. (2) **The token budget (`max-tokens` /
`MAX_TOTAL_TOKENS`) is removed from the configuration surface and from the
loop stopping conditions**: it was never enforceable during a pi call, so the
loop caps (guard re-run, review-fix, gate-fix) are bounded by the
`MAX_LOOPS` iteration cap alone, and with all remaining caps non-zero the
factory stays guaranteed to terminate.

**Cost derivation — undocumented element (planned around, per the rule that
no step may assume a component or convention the arc42 doesn't mention).**
No arc42 chapter mentions cost or pricing. The plan works around the gap by
keying the cost on the run's resolved `llm-model` setting — the only
documented adjustable LLM setting (`docs/03`: "The only adjustable LLM
setting is which configured model the run uses"; the resolved value rides the
trigger's resolved-config state, which the report job already downloads) —
with a small per-model rate table in the report stage and the rate used
listed in the report (so the listed cost is always a function of recorded
usage × listed rate, i.e. consistent, as the scenario pins). Targets select
from their runner's configured model set, so a model with no rate entry is
listed as unpriced; the coverage note lands in `docs/10` (Task 5). This is
additive to the arc42, not a contradiction.
